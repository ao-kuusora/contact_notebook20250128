# ふたりの連絡帳

夫婦・同棲カップルなど、日々の暮らしを一緒に送る2人のための連絡帳アプリです。

家事の報告、買い物のメモ、仕事の忙しさ、日記など、口頭だけでは伝え忘れやすい情報をひとつの場所にまとめ、毎日の小さなすれ違いを減らすことを目指しています。

**コンセプト：大事なことを、無理なく共有できるふたりの場所。**

## 主な機能

アカウントとカップルの紐付けを基盤に、ふたりの生活に必要な情報を共有する構成です。

### 家事の報告

- 洗濯や洗い物など、家事に関する情報を共有
- 誰が登録した情報かを記録
- 家事の状況をふたりで確認するための機能

### おつかいメモ

- 買い物など、忘れたくない用事を共有
- 必要に応じて期限を設定
- 完了状態を管理

### 仕事の忙しさの共有

- お互いの仕事や予定の状況を共有するための画面
- 相手の状況を踏まえた家事分担や予定調整をサポート

### 交換日記

- 日々の出来事や気持ちを書き残すための機能
- 忙しい日でも、相手に伝えたいことを落ち着いて共有することを目指しています

### アカウントとふたりの連携

- メールアドレスとパスワードを使ったアカウント管理
- 招待コードを利用したカップル単位の紐付け
- 登録データをカップル単位で管理するためのデータ構造

### ダッシュボードと各種画面

- 共有情報を確認するためのダッシュボード
- 家事、おつかい、仕事の忙しさ、日記、ふたりの設定などの画面
- ログインが必要な画面へのアクセス制御

※ 機能の詳細や画面構成は、現在の実装に合わせて更新していきます。

## アプリの構成

プロジェクトの主な構成要素は次のとおりです。

- `app/`：Next.js のページやルート
- `app/api/`：データの取得・登録などを行うAPI
- `prisma/schema.prisma`：データベースのモデル定義
- `middleware.ts`：ログインが必要な画面へのアクセス制御
- `tests/`：自動テスト

実際のディレクトリやファイルは、リポジトリの最新状態を参照してください。

## 動作環境

ローカルで動作させるには、以下を用意してください。

- Node.js（Next.js 14 が動作するバージョン）
- npm
- PostgreSQL
- Git
- Docker Compose（同梱の設定を利用して PostgreSQL を起動する場合）

## ローカルでの起動方法

### 1. リポジトリを取得する

```bash
git clone https://github.com/ao-kuusora/contact_notebook20250128.git
cd contact_notebook20250128
```

### 2. 依存関係をインストールする

```bash
npm install
```

インストール後、設定により Prisma Client が生成されます。必要に応じて、次のコマンドで手動生成できます。

```bash
npx prisma generate
```

### 3. 環境変数を設定する

```bash
cp .env.example .env
cp .env.example .env.local
```

Windows のコマンドプロンプトなどで `cp` が使えない場合は、ファイルをコピーして同じ名前で保存してください。

`.env` は Prisma CLI 用、`.env.local` は Next.js 用として使用します。両方のファイルに、利用するデータベースの接続先と十分に長い秘密鍵を設定してください。

### 4. PostgreSQL を起動する

Docker Compose を利用する場合：

```bash
docker compose up -d
```

既に PostgreSQL を用意している場合は、接続先に合わせて `DATABASE_URL` を変更してください。

### 5. データベースを準備する

開発環境では、Prisma のマイグレーションを適用します。

```bash
npx prisma migrate dev
```

マイグレーションファイルが存在しない、またはデータベースの初期化手順が異なる場合は、リポジトリ内の `prisma/migrations/` と現在のスキーマを確認してください。既存データがあるデータベースに対して、内容を確認せずにリセット操作を実行しないでください。

### 6. 開発サーバーを起動する

```bash
npm run dev
```

ブラウザで [http://localhost:3000](http://localhost:3000) を開きます。

## 環境変数

| 変数名 | 必須 | 説明 | 設定例 |
| --- | --- | --- | --- |
| `DATABASE_URL` | はい | PostgreSQL の接続文字列 | `postgresql://postgres:postgres@localhost:5432/contact_notebook` |
| `JWT_SECRET` | はい | セッション用トークンに使用する秘密鍵 | ランダムに生成した長い文字列 |

### 秘密鍵の生成例

macOS / Linux などで OpenSSL が利用できる場合：

```bash
openssl rand -base64 48
```

生成した値を `JWT_SECRET` に設定してください。上記は生成方法の例であり、実際の秘密鍵としてそのまま使う値ではありません。

## データ設計

Prisma スキーマでは、主に以下のモデルを定義しています。

| モデル | 役割 |
| --- | --- |
| `User` | メールアドレス、パスワードハッシュ、表示名、カップルとの紐付けなど、ユーザー情報を管理 |
| `Couple` | 招待コードを持ち、ふたりの共有単位を管理 |
| `Entry` | 家事やメモなどの共有項目を種類、内容、期限、完了状態とともに保存 |
| `ReadStatus` | 共有項目ごとのユーザー別既読状態を保存 |

共有データは `coupleId` を使ってカップル単位で管理する設計です。データへのアクセス時には、ログインユーザーの認証だけでなく、対象データがそのユーザーの所属するカップルに属しているかをAPI側でも確認することが重要です。

## 本番環境へのデプロイ

このプロジェクトは Vercel と PostgreSQL を組み合わせて公開できます。

### 1. PostgreSQL を用意する

Neon、Supabase などの PostgreSQL サービスを用意し、接続文字列を取得します。利用するサービスの案内に従い、アプリケーション用の接続先とマイグレーション用の接続先が分かれている場合は、それぞれを確認してください。

### 2. Vercel にリポジトリを接続する

GitHub リポジトリを Vercel のプロジェクトに接続し、ビルド設定を確認します。

### 3. 環境変数を設定する

Vercel の環境変数に、少なくとも以下を設定します。

- `DATABASE_URL`：本番 PostgreSQL の接続文字列
- `JWT_SECRET`：本番用に新しく生成した秘密鍵

ローカル開発用の秘密鍵を本番環境で使い回さないでください。

### 4. 本番データベースにマイグレーションを適用する

本番環境の接続先を正しく指定したうえで、マイグレーションを適用します。

```bash
npx prisma migrate deploy
```

このコマンドは、対象の `DATABASE_URL` が本番データベースを指していることを確認してから実行してください。

### 5. 公開後の動作を確認する

- トップページとログイン画面が開くこと
- アカウント登録・ログイン・ログアウトが想定どおり動くこと
- ログインしていない状態で保護対象の画面にアクセスできないこと
- ふたりの連携と共有データの登録・表示ができること
- 他のカップルのデータを参照・変更できないこと
- スマートフォンの画面幅でも主要な操作ができること

## セキュリティに関する注意

- `.env`、`.env.local`、秘密鍵、実際のユーザーデータはリポジトリに登録しないでください。
- 本番環境では推測困難な `JWT_SECRET` を使用してください。
- パスワードは平文で保存せず、ハッシュ化して扱います。
- 認証が必要なAPIでは、リクエスト元のユーザーを検証してください。
- カップル単位のデータは、ログイン済みであることだけでなく、データの所属先も確認してください。
- セッションCookie、トークンの有効期限、エラー時の応答などは、本番公開前に実装と設定を確認してください。
- デモ用の情報やテスト用アカウントを本番環境に残さないでください。

## プッシュ通知の設定

- Vercel の環境変数 `NEXT_PUBLIC_VAPID_PUBLIC_KEY`、`VAPID_PRIVATE_KEY`、`VAPID_SUBJECT` を設定します。
- `npm run build` で `prisma migrate deploy` が実行され、通知購読用のテーブルが作成されます。
- ログイン後、通知設定から端末ごとに通知を許可します。iPhone は iOS 16.4 以降で、Safari の共有メニューからホーム画面に追加し、そのアイコンから開いてください。
- 通知テストは、ふたりの端末で購読登録したあと、片方から新しい投稿を作成して確認します。
